# 头像与首页改动独立复核

只读复核主代理的 `api/me/avatar/route.ts`、头像测试、首页/能力卡/统计/封面文案与 `advanced-settings.tsx`。未修改这些产品文件，未连接生产。未发现本次改动的阻断项。

## 头像

- 鉴权及每用户 5 次/60 秒计数先于 `request.formData()`，非法、未登录及超限路径均不会到存储。
- 200 KiB 与允许 MIME 先筛选，随后把原始 Buffer 交给 `checkGenerationInput`，`builtIn: true` 防止审核关闭或配置失效时放行。
- 共享真实调用链为配置/既有暂停检查→`assertModerationImages`（实际格式、MIME、静态图检查）→本地图片模型→远端图片审核；代码没有先上传后审核或只信前端 MIME 的新旁路。
- S3 `PutObjectCommand`、本地 data URL 写回和 `db.user.update` 均在审核允许后。审核 false/throw 不产生这些写入。使用同一份原始 Buffer，不存在送审副本与实际头像内容不同的替换。
- 公开作品 mapper 的头像保持 null；头像返回给当前用户的个人资料不等于公开作者头像。当前实现不对历史头像补审，不新增媒体 token，也未改变 S3 已有对象保留规则。
- 头像 route 单测 mock 共享审核函数，能证明原字节和写入顺序；格式/模型本身由原有审核测试覆盖，不能把此 mock 测试说成真实在线模型验收。

## 首页与高级选项

- 主页对匿名用户也读取 API 开关，读取失败按 false。能力卡和页脚传相同状态，接口授权仍由服务端原有 API guard 执行；没有为了隐藏入口放松权限。
- 能力卡显式过滤 API 项，统计从虚构历史数字改为现有 4 张批次、16 张参考图、每人 5 张/分钟的实际限制。原可见性/动画/减少动效逻辑仍保留。
- 内置渠道不再显示无效的“审核策略”选择；自定义渠道在该功能开放且被选择时仍有原下拉。它只是反映已有 Worker 内置渠道强制审核的行为，没有改 payload 或服务端安全策略。
- 登录封面通用文案与根布局描述去掉不准确的邀请/自填渠道宣传，不宣称邮箱注册已被关闭。
