# 技术设计

采用固定 NSFWJS 4.4.0 自带的 MobileNetV2Mid 模型、TensorFlow.js/WASM 4.22.0，在一个独立 Node Worker 线程中处理图片。仅以原生 ESM 导入 core 和所选模型，避免 CJS 包装展开大字符串导致约1GiB冷加载峰值。Node24原型冷加载约0.318s、峰值RSS约266MiB、热图约37ms、16张串行约0.66s；仍需生产Alpine实测。

共享 checkGenerationInput 是所有站内生成的门禁；在 callModerationAi 中复用 assertModerationImages 后逐图本地检查，全部通过才构造远程请求。纯文本不初始化图片模型。使用现有 ContentReview 表记录本地拒绝，阻断结果携带准确 aiModel，category沿用sexual；不新增表或管理设置。

固定策略先使用 Porn 或 Hentai >=0.2、Sexy >=0.8 拒绝；它是保守业务阈值，不是经过校准的风险概率，也不是CSAM分类。全部五类分数必须完整、有限且在0～1之间；异常不能当作通过。保留既有远程审核作为第二层，不根据本地通过绕过它。

一个活动请求、最多两个等待请求，已接纳整请求压缩原图合计最多256MiB；每请求8秒总截止包含排队/模型加载/全部逐图检查。超量或等待失败返回现有审核不可用提示。保留原16张数量，每次仅复制当前图到线程；原图不得detach或改写。64MP解码限制并先缩小到模型输入尺寸再导出RGB，WASM内部线程数为1。此限额不等于整个HTTP服务器的全局内存上限，路由原先已读取入站文件。

实际预处理验证发现Sharp在同一管线中先缩放再去alpha，会丢失透明区域RGB。仅有alpha的图片改为先应用EXIF/去alpha输出有界RGB，再另起管线缩小；64MP中间缓冲192MB。桌面单张大图峰值451MiB、连续16张约637MiB，目标容器另测，不能套用普通图266MiB数据。普通无alpha仍先缩小，不改变外部收到的原字节。

活动超时需终止旧线程并等待退出后才能再建，避免失控线程堆积；worker错误清理所有待审请求和预算，短暂退避后允许重建。空闲线程unref，纯文本与无关HTTP请求不等待本地推理。

运行脚本放在 Docker 已复制的 scripts 目录，依赖与模型随固定包/lock进入镜像；不新增Python、数据库或对外端口。模型包的engines声明Node22.13.0过于具体，与现有Node24不同；仅在Node24/实际Alpine真实运行验证通过后发布，不修改服务Node版本。

只允许从固定本机依赖/模型读取，不在请求时拉远程模型、上传图片或信任图片里的指令。超时、worker退出及队列饱和必须释放资源并给现有审核不可用提示。

本任务使用已授权的提交/部署流程。专用CSAM服务的模型查询与纯色图审核探测均404，仅说明本次凭据/服务不可用，不替用户提交审批资料。普通图生图继续提供，不能以预审异常为由全站删除参考图入口。
