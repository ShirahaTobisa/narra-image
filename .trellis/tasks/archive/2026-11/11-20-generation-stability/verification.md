# 登录验证与生图修复记录

日期：2026-11-20。仓库：`ShirahaTobisa/narra-image`。基线：`2087e89`，本地分支：`fix/site-stability`。

## 已修问题

| 触发方式 | 修复后的行为 |
| --- | --- |
| 登录断网、网关返回 HTML 或请求一直等待 | 最多等待 30 秒；错误留在表单，保留输入，可重新验证后再试 |
| 验证脚本失败、过期或未就绪 | 15 秒加载截止；清理失败状态，直接点击“重新验证”，无需刷新整页 |
| 连点提交，或请求期间切换登录模式/离开页面 | 拦截重复请求；旧结果不重置新验证码或把用户拉回旧页面 |
| 签到、领取邀请码请求异常 | 操作处显示可读错误；领取批次共用防重复提交，失败后重置一次性验证码 |
| 登录页配置自定义封面 | 不再等待用不到的精选作品查询；封面读取失败不影响表单显示 |
| 复用数据库存图或旧 S3 图片 | 检查拥有权/公开资格及精确数据库记录后复用和下载，保留内网防护与大小限制 |
| Canvas 带参考图生成 | 拥有权确认后的参考图字节也参与审核，拒绝后不创建任务或扣费 |
| 审核服务返回空数据、缺字段或错误类型 | 按服务不可用拒绝生成，不把坏响应当作审核通过或用户违规 |
| 图生图失败后重试 | 保留原模型、参数、渠道类型和参考图；缺图时明确提示 |
| 混用历史图和新上传图片 | 按界面顺序入队，避免“图片一/图片二”颠倒 |
| 切换会话，或只传图/一个字就提交 | 切换时清除图生图模式；发送条件与服务端两字符要求一致 |
| 多次主动取消任务 | 取消记录不触发渠道故障切换，也不遮住真实失败记录 |

公共逻辑集中在请求、登录封面、本站图片三个小模块；重试继续复用已有配置转换。没有数据库迁移，也没有修改积分政策。

## 安全与依赖

- 补齐 Canvas 图片送审和审核响应校验；不再将审核上游错误正文写入错误日志。
- 旧图片兼容仍要求本站来源和访问资格，不开放通用代理。受管理图片继续执行现有签名、可用性与存储检查。
- 更新锁文件和必要的依赖约束。最终 `pnpm@10.32.1 audit --json` 所报各级漏洞均为 0；这是依赖扫描结果，不代表完成全面安全审计。
- 独立审阅提出的迟到请求影响新页面、取消任务查询顺序和多余封面查询均已修复并增加回归。
