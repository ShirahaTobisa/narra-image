# 普通网页参考图上传前准入

## 实现

- `src/app/api/generate/route.ts`：审核和每用户五张额度顺序不变。普通网页在 reference epoch → User 锁的短事务中复核账号、封禁、实际余额、会话归属和两个未完成任务上限，创建并扣费一个 `workerManaged:false` 的 PENDING 任务。已存在的参考 URL 仍在该事务内绑定受保护的历史根。
- 成功占位后，输出预留和新文件上传均在事务外完成。因此已有两个任务、以及并发争最后一个名额的失败请求，都不预留输出、不保存新参考图。上传全部成功后，第二个短事务绑定最终有序来源，并仅对 PENDING、未取消、未退款、仍 unmanaged 的任务启用 Worker；输出 reservation 与启用在同一事务绑定。
- 最终事务复核 bannedAt，但不新增 User 行锁，避免与取消退款的 job → User 锁形成倒序。此重读之后的封禁竞态由本批 Worker 首次提交检查收口。
- Canvas 仍使用原有 prepare/commit/replay 单事务，成功后在普通文件上传代码之前返回；未改其名额规则、退款归属或未知提交恢复逻辑。
- `src/lib/generation/job-refund.ts` 复用现有补偿，增加 `onlyUnmanagedPending`。它在读取和条件更新两处限制未启用任务；条件竞争失败会告诉调用方保留输出预留。默认调用方行为不变。
- 普通任务 ID 在占位提交前确定：占位已提交但回执丢失时仍能寻找并补偿尚未启用的任务；启用已提交但回执丢失时，不退款、不关闭输出预留，继续由 Worker/已有查询流程处理。

## 范围和取舍

- 修复保证是“被名额拒绝的请求不产生新参考图写入”，并非所有网络失败都不会留下孤儿。部分文件成功、随后另一文件失败或上传期间取消时，已写对象仍由既有确切身份/引用保护/清理流程管理，未新增直接删除或减账。
- 多一个短数据库事务，换来持久、可取消的上传准备状态；事务内没有文件或网络存储 I/O。准备中的任务在已有历史查询中显示 PENDING，正常取消仍能退回积分。上传失败保留 FAILED 记录；未成功保存的原文件无法从服务器恢复。
- 未扩大 Worker、本机审核、图片大小、任务数或全站 5 GB 上限。未新增 schema 字段或新的队列组件。
